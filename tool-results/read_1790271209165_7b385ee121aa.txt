   370→   370→// PHASE 3 — Secure Digital Document Management (spec §5/§9/§50/§51).
   371→   371→//
   372→   372→// IMMUTABILITY MODEL (spec §2/§35): a COMMITTED CaseDocument row is
   373→   373→// a legal record. After commit, documentId, caseId, binary content,
   374→   374→// sha256Hash, originalFilename, mimeType, fileSize, storageKey,
   375→   375→// uploadedBy identity and committedAt are FROZEN — no API mutates
   376→   376→// them, and documents are never hard-deleted. Corrections and
   377→   377→// supplements are NEW immutable rows linked through
   378→   378→// DocumentRelationship; replacement flips the original to
   379→   379→// SUPERSEDED (a status, never a deletion).
   380→   380→//
   381→   381→// TWO-PHASE COMMIT (spec §12/§22/§23): the binary is validated,
   382→   382→// hashed (SHA-256 over plaintext), encrypted (AES-256-GCM) and
   383→   383→// stored BEFORE metadata persists. A Document row exists only from
   384→   384→// commit onward; failures are tracked on DocumentUploadSession and
   385→   385→// staged objects are cleaned up or quarantined — a failed upload
   386→   386→// can never appear as a valid document.
   387→   387→//
   388→   388→// STORAGE: files live OUTSIDE /public under opaque server-generated
   389→   389→// keys (cases/{case-uuid}/documents/{uuid}/object); the original
   390→   390→// filename is metadata only. SQLite keeps metadata only.
   391→   391→// ============================================================
   392→   392→
   393→   393→model CaseDocument {
   394→   394→  id                     String    @id @default(cuid()) // internal id — never exposed as storage path
   395→   395→  documentId             String    @unique // public identity: DOC-MP-IND-2026-000001 (backend-generated, immutable)
   396→   396→  caseId                 String
   397→   397→  case                   Case      @relation(fields: [caseId], references: [id], onDelete: Restrict)
   398→   398→
   399→   399→  // classification
   400→   400→  title                  String
   401→   401→  description            String?
   402→   402→  documentType           String    // DOCUMENT_TYPES registry
   403→   403→  documentCategory       String?   // DOCUMENT_CATEGORIES registry
   404→   404→
   405→   405→  // file facts — frozen after commit (spec §35)
   406→   406→  originalFilename       String    // preserved as metadata only, never a storage path
   407→   407→  storedFilename         String    // server-generated <uuid>.bin
   408→   408→  mimeType               String    // server-detected via magic bytes
   409→   409→  fileExtension          String
   410→   410→  fileSize               Int
   411→   411→  storageProvider        String    // STORAGE_PROVIDERS registry
   412→   412→  storageKey             String    // opaque: cases/{case-uuid}/documents/{uuid}/object
   413→   413→  sha256Hash             String    // integrity fingerprint over PLAINTEXT, computed pre-encryption
   414→   414→  encryptionStatus       String    // ENCRYPTION_STATUSES registry
   415→   415→  keyReference           String?   // key VERSION reference — never the key material
   416→   416→
   417→   417→  // lifecycle & security
   418→   418→  status                 String    @default("COMMITTED") // DOCUMENT_STATUSES
   419→   419→  classification         String    // DOCUMENT_CLASSIFICATIONS
   420→   420→
   421→   421→  // origin — frozen after commit; always derived server-side
   422→   422→  uploadedByOfficerId    String

   424→   424→  uploadedByDepartmentId String
   425→   425→  uploadedByDepartment   Department @relation("documentUploaderDepartment", fields: [uploadedByDepartmentId], references: [id], onDelete: Restrict)

   427→   427→  // dates are distinct (spec §28): documentDate is the business date,
   428→   428→  // createdAt is upload time, committedAt is commit time.
   429→   429→  documentDate           DateTime?

   431→   431→
   432→   432→  committedAt            DateTime?

   434→   434→  uploadSessionId        String?   @unique
   435→   435→
   436→   436→  relationshipsAsSource DocumentRelationship[] @relation("docRelationshipSource")
   437→   437→  relationshipsAsTarget DocumentRelationship[] @relation("docRelationshipTarget")
   438→   438→  evidenceRelationships EvidenceDocumentRelationship[] @relation("evidenceRelationshipDocument")
   439→   439→  events                DocumentEvent[]
   440→   440→
   441→   441→  createdAt              DateTime  @default(now()) // uploaded at
   442→   442→  updatedAt              DateTime  @updatedAt
   443→   443→
   444→   444→  @@index([caseId])
   445→   445→  @@index([caseId, status])
   446→   446→  @@index([documentType])
   447→   447→  @@index([classification])
   448→   448→  @@index([status])
   449→   449→  @@index([uploadedByOfficerId])

   688→   688→// PHASE 4 — Immutable audit architecture (spec §22-§31/§48-§55).
   689→   689→//
   690→   690→// APPEND-ONLY: no API ever updates or deletes an AuditEvent; the
   691→   691→// SQLite layer additionally enforces this with RAISE(ABORT)
   692→   692→// triggers (spec §58 — applied by scripts/apply-sqlite-guards.ts).
   693→   693→// Corrections are NEW events, never edits (spec §24).
   694→   694→//
   695→   695→// HASH CHAIN (spec §25/§26): event_hash = SHA-256(canonical payload
   696→   696→// + previous_event_hash); canonical serialization is ONE shared
   697→   697→// implementation (CanonicalAuditSerializer, spec §55) — field
   698→   698→// order fixed, metadata keys sorted, timestamps ISO-UTC. The chain
   699→   699→// starts at the documented AUDIT_GENESIS hash (spec §27).
   700→   700→//
   701→   701→// caseId/documentId/evidenceId store PUBLIC identifiers WITHOUT
   702→   702→// foreign keys by design: audit records are self-contained, they
   703→   703→// outlive resource lifecycles, and the ledger must never be
   704→   704→// blocked by (or cascade from) resource management. Actor fields
   705→   705→// ARE foreign keys with Restrict — audit presence prevents
   706→   706→// destroying actor identity.
   707→   707→//
   708→   708→// HONEST BOUNDARY (spec §29): a database hash chain is
   709→   709→// tamper-EVIDENT against application-level and casual DB tampering;
   710→   710→// it does NOT stop a privileged infrastructure administrator who
   711→   711→// can rewrite the whole table and every hash. External anchoring
   712→   712→// via LedgerAnchor (spec §30/§31) is the production extension.
